# 检查项目

## 1. 代码规范问题
- 重复代码：检查是否有重复的配置、函数定义
- 配置管理：检查配置是否集中管理，是否有敏感信息硬编码
- 变量命名：检查变量命名是否清晰、符合 Python 命名规范
- 代码注释：检查关键逻辑是否有注释说明
- 函数长度：检查是否有过长的函数（超过 50 行）

## 2. 异常处理
- try-catch 覆盖：检查外部调用（API、文件IO）是否有异常处理
- 异常信息：检查异常是否记录了详细信息（错误类型、堆栈、上下文）
- 异常传播：检查是否有吞掉异常不处理的情况
- 空值检查：检查是否对可能为空的变量进行了检查

## 3. 数据传输失败处理
- API 调用重试：检查飞书 API 调用是否有重试机制
- 超时设置：检查网络请求是否设置了超时时间
- 失败回退：检查数据传输失败后是否有降级或备用方案
- 状态码检查：检查是否正确处理了 API 响应的状态码
- 网络异常：检查是否处理了网络连接异常、超时等情况

## 4. 日志记录
- 日志完整性：检查关键操作是否有日志记录（API调用、数据写入、异常）
- 日志级别：检查日志级别使用是否合理（INFO/WARNING/ERROR）
- 日志内容：检查日志是否包含足够的上下文信息（用户ID、操作类型、参数等）
- 敏感信息：检查日志是否泄露了敏感信息（密钥、密码等）
- 日志格式：检查日志格式是否统一、易于解析

## 5. 线程安全问题
- 全局变量：检查全局变量的使用是否线程安全
- 锁机制：检查并发操作是否使用了适当的锁
- 竞态条件：检查是否存在竞态条件

# 检查流程

1. 读取指定文件或扫描项目中的所有 Python 文件
2. 逐行分析代码，识别上述问题
3. 按优先级排序问题（严重程度：高/中/低）
4. 生成详细的检查报告，包括：
   - 问题位置（文件名:行号）
   - 问题类型
   - 问题描述
   - 建议的修复方案
   - 示例代码
